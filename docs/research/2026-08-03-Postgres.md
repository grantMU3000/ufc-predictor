## Key ideas

- For primary keys, INT tops out at 2,147,483,647. Hitting this ceiling will cost a lot of time to fix. Default to BIGINT unless your table stays small (Probably will)
- There are different types of primary keys (natural, surrogate & UUID). Will stick with natural since the data most likely won't change
- Use DECIMAL/NUMERIC over REAL/FLOAT to avoid sums drifting (For approximations, REAL/FLOAT is okay)
- Use TIMESTAMPTZ over TIMESTAMP if you care about timezones (Relevant considering ppl from different zones could view this)
-  Aim for 3NF by default, then denormalize until it works (Production rule)
- Define Foreign key relationships early. Retrofitting later is expensive
- Foreign keys enforce referential integrity
- RESTRICT fails loudly
- Choose names for data accordingly. Renaming makes downstream tasks like deployment highly incident-prone
- tables: plural snake_case; columns: singular; constraints/indexes: typed prefixes
- Implement constraints & validation rules early
- Plan for schema evolution/retrofitting since schemas will change over time. First schema won't be the same as the last one
- Add changes first, then drop the old one (expand-contract pattern). Never rename in place
- Document the schema by using COMMENT ON. This allows documentation to live within the schema
- Add in auditing to track history
- Indexing helps deal with speed of scalable databases 
- It helps find rows faster without scanning the entire database (Like the Index in the back of a book, or a table of contents)
- PostgreSQL uses a B-tree to index tables 
- The tree traversal typically only takes 3-4 steps even if tables have millions of rows
- B-tree indexes work well for range queries like WHERE price > 50 AND price < 100
- You can create indexes on individual columns
- EXPLAIN ANALYZE is an important tool for understanding how PostgreSQL executes queries because it will tell you how long certain queries took, amount of rows it looked at, etc.
-  If you se Seq Scan on a large table with a WHERE clause, you probably need an index
