## Key ideas
**Source 1**
- The decision tree is based on errors made by previous trees
- Uses 8-32 leaves typically
- The initial prediction is based on the average of all the values of the variable we want to predict
- It stores errors by taking the observed value minus the predicted value & storing that (residual. This column holds this calculation for each row)
    - Then, we use the features to help predict residuals
- These trees can be used in combination with the initial prediction to make a new prediction from training data
- The trees can easily overfit, so learning rate is used to scale the contribution from the new tree
    - So this leads to small steps in the right direction instead of a single big step
    - This overfitting leads to lower bias, but higher variance
- Taking lots of small steps in the right direction leads to better predictions with a testing dataset (lower variance)
- With each step, we add the results of the decision trees to the initial prediction
- The leaves of the trees hold the residuals of the previous prediction (Typically averaged out)

**Source 2**
- LightGBM uses histograms to bucket data into discrete bins (Much faster/lightweight compared to traditional algorithms)
- Doesn't need to sort all datapoints perfectly
- LightGBM chases errors and tries to correct them, as opposed to XGBoost, which chases symmetry
- You need to constrain how complex your data can get (# of leaves) to prevent overfitting
- We lose a bit of data, but that can help prevent overfitting
- LightGBM should be used for massive datasets & if you have latency concerns, but XGBoost is best for small/medium datasets since they're less prone to overfitting
- Tune # of leaves first to control complexity (instead of max depth)
- Finding a split point in a decision tree costs a lot of computation because you're sorting millions of rows
    - Instead, the split is just on the bins of data
