## Key ideas
- AI model versioning is necessary for reproducing models, and helps with diagnosing model problems downstream
- Organizations with good versioning practices ship models faster & experience fewer production failures
- You should track every artifact, decision, and dependency that defines a model
    - This ensures any model version can be reproduced, compared, audited, or rolled back
- Reproducibility means given the same input data, code, and configuration, a training run produces identical results.
    - The best way to enfoce reproducibility is by versioning the entire execution context 
- Every model version should be immutable once registered. Don't overwrite artifacts in place or else this will mess up audit trails & rollback
    - Create a new version for every change, no matter how small
- End-to-end lineage: prediction --> model --> training data --> code
    - This chain must be unbroken. Otherwise, teams can't determine the root cause when models behave unexpectedly
- Models move through stages (experimentation, validation, staging, production, and archive). Each transition should require approval and leave a record
    - MLflow's model registry supports stages & version-level annotations that explain why transitions occur
- Branching discipline is important for parallel experimentation 
    - Data scientists run many experiments simultaneously, and without branching discipline, artifacts collide & results become unpredictable
    - Create one branch per experiment, commit in small chunks, and merge only after automated validation checks pass
    - This keeps the main branch clean & production-ready while letting researches explore
- Each model version should link to the exact Git commit that produced it
