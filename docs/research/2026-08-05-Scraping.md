## Key ideas
- Respect robots.txt, and check for an official API/bulk export b/c you may not even need to scrape
- Try scraping during off-peak hours & pace requests so it doesn't look like an overload event
- embedded JSON is more stable & cheaper to parse. Check the Network tab, or the page source
- Classify errors as retryable or terminal
- Cache responses & deduplicate requests. Have conditional requests & a visited-URL set
- Monitor your scrapers b/c a scraper can return HTTP 200 while extracting nothing
- Keep in mind that sites may change over time, so don't key to a specific CSS class/path
- Robots.txt is a machine-readable statement of what automated traffic can access & how fast. It's up to the crawler to comply
- A 10-second delay between requests to the same domain is a conservative starting point
- Crawl-delay should be looked at to figure out the correct pace
- Don't do async scrapes
- HTML parsing is still good for server-rendered pages with no data layer
- Use headless browsers for Javascript-heavy pages (wrong default for everything else). Try plain HTTP client first b/c these are memory-hungry and run slower per request
- Distribute the signals that identify a request across pools so that no single identity accumulates suspicious volume on its own
- Rotating proxies, user agents & fingerprints helps avoid IP bans because it avoids false-positive blocks
- Retry the retryable errors with exponentially growing waits, and cap the attempt count
- Timeouts, 429 & 503 are usually retryable. 404, 401/403, and schema mismatch is typically terminal
- Log everything b/c it makes monitoring easier (URL, status code, latency, retry count)
- Retrying errors immediately after w/ no backoff increases load on a limiting server. This can extend the block
- Treat responses as signals not challenges
- Conditional requests like ETag & Last-Modified for revisit workloads
- Parse & validate while you scrape to avoid a large unvalidated batch with a bunch of problems
- A scraper needs the same observability as any other production service (Use 3 metrics: Request health, extraction health, and freshness)
